# [설계] 이미지 검색 대체 입력 — Phase 2

**작성일**: 2026-05-22
**상태**: 설계만, 구현 X
**배경**: BE `image_search_node` + GCS 업로드 인프라(PR #82)는 갖춰져 있지만, 실 사용 환경(모바일 카메라 권한, GCS 버킷 설정, 1시간 signed URL 만료 등)에서 사용자가 이미지를 실제로 못 넣을 가능성이 높음. 비주얼 유사도 검색을 대체할 다른 입력 경로 필요.

---

## 문제 정리

### 사용자가 이미지로 표현하려던 의도
1. **분위기/무드 매칭** — "이 사진 느낌의 카페 찾아줘"
2. **장식/메뉴 특정** — "이런 디저트 파는 곳"
3. **장소 자체 식별** — "이 사진 어디야?"
4. **시각 스타일 참조** — "한옥/모던/레트로/북유럽"

### 이미지가 못 들어갈 때의 실효 손실
- (1), (4) 는 형용사/명사로 텍스트 표현 가능 → 충분히 대체
- (2) 는 메뉴명/카테고리 명사로 대체 가능 (예: "크로플 파는 카페")
- (3) 는 텍스트로는 거의 불가능 — 그러나 chat agent 서비스 본 목적이 아님

→ **(1), (2), (4) 만 우선 커버해도 OX 사용 경험은 80%+ 회복 가능**.

## 대체 입력 옵션

### A. 무드/스타일 칩 (Mood Chips)
ChatInput 위에 작은 추천 칩 그룹. 사용자가 1~3개 선택하면 query 에 자동 prefix.

**칩 카테고리 예시**:
- 분위기: 조용한 / 활기찬 / 감성적인 / 모던 / 레트로 / 한옥
- 사람 수: 혼자 / 둘이 / 모임 / 데이트
- 시간대: 아침 / 점심 / 저녁 / 야경
- 가격대: 저렴한 / 중간 / 프리미엄

**UX**:
- 칩 클릭 → 칩이 칩 행에 "선택됨" 상태로 남음
- 메시지 전송 시 칩 텍스트가 자동으로 query 앞/뒤 prefix
- 전송 후 칩 클리어

**구현**:
- `ChatInput` 위 `MoodChips` 컴포넌트 신설
- 선택된 칩을 부모 state 로 관리
- onSend 가 칩 텍스트와 사용자 입력을 합쳐서 전송

**Pros**: 가장 가벼움. BE 변경 0. 사용자가 입력 노력 적음.
**Cons**: 칩 catalog 가 도메인 지식. 잘못 큐레이션하면 무의미.

---

### B. 장소 참조 (Place Reference Picker)
"이 장소 같은 곳" 패턴. 사용자가 최근 본 / 북마크 / 채팅에 등장한 장소 중 하나를 선택 → 그 장소 정보가 query 컨텍스트로 들어감.

**UX**:
- ChatInput 옆 "북마크/최근 참조" 아이콘 (📍)
- 클릭 → 작은 시트 열림. 북마크된 장소 + 현재 대화에 나온 장소 리스트
- 1개 선택 → 칩으로 표시 (X 로 제거 가능)
- 전송 시 query 본문에 `[참조: {place_name}]` 형태로 끼움

**구현**:
- `useBookmarkStore` + 현재 thread 의 `message.places` 합집합
- `PlaceReferencePicker` 신설 (모달/드롭다운)
- 선택된 reference 를 chatStore 또는 ChatInput state 로 관리
- BE 가 query 의 `[참조: ...]` 패턴 인식하도록 협의 또는 자연어로만 사용 ("강남 ABC 카페 같은 곳")

**Pros**: 의도 명확. BE 변경 최소 (자연어 prefix 만으로 동작).
**Cons**: 최근 본 장소가 없으면 무의미. 데이터 의존성.

---

### C. URL 붙여넣기 → 콘텐츠 추출
사용자가 인스타/블로그/네이버 지도 URL 을 채팅창에 붙여넣으면, FE 또는 BE 가 OG 메타데이터/장소 정보 추출 → "이거 같은 곳 추천" 으로 처리.

**UX**:
- ChatInput 이 URL 패턴 자동 감지 (`https://...`)
- 감지되면 "📎 링크 분석 중" 칩 표시
- BE 가 URL 메타데이터 fetch → 장소명/카테고리 추출
- query 에 추출 정보 prefix

**구현**:
- FE: URL regex 감지 + UI 표시
- BE: 새 `extract_url_metadata` 노드 또는 image_search_node 확장
- BE 변경 큼

**Pros**: 이미지 의도와 가장 비슷한 UX (외부 자료 참조).
**Cons**: BE 작업 큼. 인스타/블로그가 보통 외부 fetch 차단 → 신뢰성 낮음.

---

### D. 음성 입력 (Voice → Text)
BE 가 STT 까지 처리하면 음성 메시지 가능. 다만 본 주제와 살짝 벗어남.

→ **Phase 2 범위 밖**. 별도 논의.

## 추천 조합

**Phase 2a (즉시, FE only)** — Option A + B
- **무드 칩**: `ChatInput` 위에 5~10개 칩 (분위기/시간대/사람 수). BE 변경 0
- **장소 참조**: 북마크/최근 장소 picker. 자연어 prefix 만 사용해서 BE 변경 0
- 두 가지를 합쳐 사용 가능 — 예: 칩 "감성적인" 선택 + 참조 "강남 BLUE BOTTLE" + 입력 "근처에서 비슷한 곳" → BE 한테 "감성적인 분위기, 강남 BLUE BOTTLE 같은 카페 근처에서 비슷한 곳" 전송

**Phase 2b (선택)** — Option C
- URL 자동 감지 + BE 메타데이터 추출 노드 신설
- BE 협의 필요

## ChatInput UI 흐름 (Phase 2a 적용 후)

```
┌─────────────────────────────────────────────┐
│ [📍 강남 BLUE BOTTLE x] [📷 사진 1장 x]     │  ← 참조 / 사진 칩 (있을 때만)
├─────────────────────────────────────────────┤
│ [조용한] [감성적인] [데이트] [야경] [모던]  │  ← 무드 칩 (showChips 모드일 때만)
├─────────────────────────────────────────────┤
│ [📷] [📍] 메시지 입력...               [↗]  │  ← 입력 row (사진 + 참조 + 텍스트 + 전송)
└─────────────────────────────────────────────┘
```

기존 사진 첨부 UI 는 살려두되, 안 들어가는 환경에서도 무드 칩 + 참조로 대체 가능.

## 기술 메모

### 자연어 prefix 패턴 (BE 변경 없이 동작)
BE LLM 이 자연어를 그대로 이해하므로 prefix 만 잘 만들면 됨:
- 무드 칩: `"[분위기: 감성적인, 시간대: 야경] " + 사용자 입력`
- 장소 참조: `"[참조: 강남 BLUE BOTTLE] " + 사용자 입력`
- 또는 더 자연스러운 형태: `"강남 BLUE BOTTLE 같은 분위기로 근처 카페 추천해줘"`

LLM 친화적인 자연어가 brackets 보다 결과 안정성 높음. 칩 라벨을 자연어 어구로 만드는 게 좋음.

### 칩 데이터 위치
- `src/lib/mood-chips.ts` (신규) — chip catalog 상수
- 기획 변경 잦으면 BE 가 chips API 로 내려주는 방식도 가능 (장기)
