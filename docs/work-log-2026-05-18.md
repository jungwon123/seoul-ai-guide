## PR #66 — 장소 북마크 BE 연동 (`/users/me/place-bookmarks`)

**Merge commit**: `7ad20a2`
**Branch**: `feat/place-bookmarks-api`

### 배경
BE PR #80 (#102 머지) 의 장소 북마크 3 엔드포인트와 FE 연동. 기존엔 PlaceCard 의 ☆ 버튼이 브라우저 localStorage 에만 저장돼 다른 기기/브라우저에서 안 보였음.

### 엔드포인트
- `GET /api/v1/users/me/place-bookmarks` — 목록 (cursor pagination, limit 기본 20)
- `POST /api/v1/users/me/place-bookmarks` — 저장 (중복 시 idempotent 200)
- `DELETE /api/v1/users/me/place-bookmarks/{bookmark_id}` — 소프트 삭제 (204)

### 변경
- `src/types/api.ts`:
  - `PlaceBookmarkItem`, `PlaceBookmarkCreateRequest`, `PlaceBookmarkListResponse` 타입 신설
- `src/lib/api.ts`:
  - `placeBookmarksApi.{list, create, delete}` 추가
- `src/stores/bookmarkStore.ts`:
  - `placeBookmarkIds: Record<place_id, bookmark_id>` 매핑 신설 + localStorage 캐시 (`seoul-ai-place-bookmark-ids`)
  - `toggle/add/remove`: 로컬 optimistic 업데이트 + BE 동기화 (fire-and-forget). 실패는 silent — 다음 `loadFromServer` 가 진실 복원
  - `loadFromServer`: 메시지/장소 북마크를 `Promise.allSettled` 로 병렬 fetch. BE 응답을 진실로 받아 localStorage 캐시 덮어쓰기
  - `placeToCreateRequest` / `placeBookmarkItemToPlace` 양방향 변환 helper

### 동작 흐름
1. 로그인 → `App.tsx` `useEffect` 가 `loadFromServer` 호출 → 메시지/장소 북마크 둘 다 fetch
2. PlaceCard ☆ 클릭 → `toggle(place)` → UI 즉시 반영 + BE POST → 응답의 `bookmark_id` 를 매핑 저장
3. ☆ 해제 → 매핑에서 `bookmark_id` 조회 → BE DELETE (소프트 삭제)
4. 다른 기기 로그인/새로고침 → 1번부터 다시 → 동기화

### 호환성
- `toggle/add/remove` 시그니처 유지 (void 반환). PlaceCard, PlaceCarousel, PlaceOverlayItem, BookmarkPanel 사용처 수정 0
